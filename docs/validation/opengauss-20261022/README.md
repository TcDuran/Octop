## 1. 环境隔离与权限

- 管理连接仅用于读取版本、权限、数据库目录，以及创建/删除本轮临时库；未向原有 `plat` 库的表、函数、索引或数据发出变更语句。
- 临时库使用 `octop_verify_20261022_<随机值>`，恢复库使用 `octop_verify_restore_20261022_<随机值>`，以 `template0`、PG 兼容模式创建，不使用原有库作为模板。
- 每次写入连接均校验当前库名与本轮记录的数据库 OID；清理仅删除本轮创建且 OID 匹配的数据库。
- `plat` 角色的 `rolcreatedb`、`rolsuper` 虽均为 false，但实际 CREATE DATABASE / DROP DATABASE 成功。以实测权限为准，不能仅据这两个标志判断该环境的建库能力。
- 只把新建临时库 DSN 传给会清理 public schema 的 PG 集成测试，从未把原有 `plat` 库 DSN 传给这些测试。
- 未启动数据库服务、修改现有实例参数、创建角色或调用外部 LLM。

## 2. 实际通过的基础能力

| 项目 | 实测结果 | 限定范围 |
| --- | --- | --- |
| CREATE TABLE / SEQUENCE / INDEX | 显式 sequence、自增默认值、主键、唯一约束、Astore、生成列、GIN、并发建索引成功 | 样例表，不代表全部 Octop DDL 已适配 |
| CREATE FUNCTION | 4 个兼容函数原型创建并调用成功 | 不是 PostgreSQL 同名函数的完整等价实现 |
| 真实 DML | INSERT / UPDATE / DELETE RETURNING 成功 | 使用隔离库合成数据 |
| 全文检索 | 生成列可检索，更新基础列后自动重新计算 | 使用内置 simple 分词与 GIN |
| 延迟外键 | Astore 中先插子行、再插父行成功；无父行提交被 23503 拒绝 | 实际约束已验证，未删除外键规避 |
| 原生 UPSERT | 插入、更新、条件拒绝、重复忽略、RETURNING 成功 | 插入/更新 rowcount=1；条件拒绝/忽略 rowcount=0 |
| 一次性消费 | 两个并发连接执行带条件的 UPDATE RETURNING，仅一个成功 | 合成登录码样例，非完整 SSO 流程 |
| SKIP LOCKED | 一个连接锁定首行，另一个连接只获得第二行 | 两连接实际持锁验证 |
| advisory lock | 稳定 64 位锁键原型下，首个事务获得锁，第二个事务未获得 | 不宣称与 PG 原哈希算法一致 |

兼容函数原型的实际边界：

- `to_regclass`：缺少关系返回 NULL，已存在的限定名可解析；未穷尽大小写、转义和临时关系场景。
- `to_jsonb`：已验证整数、数组、整行及 SQL NULL；未穷尽所有 PostgreSQL 类型和时区行为。
- `hashtextextended`：MD5 派生稳定 bigint，验证不同 seed 和事务锁；未做碰撞与性能压力测试。
- `jsonb_path_query_array`：只支持数组输入及 `$[*]`；其他路径和标量明确报错。不是完整 JSONPath，也未实现 PG 对标量的 lax 行为。

## 3. 已复现的兼容问题及处理方向

| 编号 | 实测失败 | 处理方向 |
| --- | --- | --- |
| OG-01 | `GENERATED BY DEFAULT AS IDENTITY` 在 BY 处报 42601，控制面直接 run_migrations 同样失败 | openGauss baseline 使用显式 sequence + DEFAULT nextval；保留整数宽度与序列归属 |
| OG-02 | 真实 INSERT 的 `ON CONFLICT` 报 42601 | 按业务冲突语义逐项适配；简单场景使用原生 UPSERT |
| OG-03 | 原生 UPSERT 更新唯一索引列报 0A000 | SSO 等场景使用专门事务流程 |
| OG-04 | 多唯一约束下，原生 UPSERT 会因另一个唯一键冲突而更新已有事件 | 已实际复现目标冲突不等价；不能全局替换 ON CONFLICT |
| OG-05 | `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 报 42601；检查点迁移在相同语法处失败 | 独立版本控制，或在同一事务和锁协议下检查元数据，再执行普通 ADD COLUMN |
| OG-06 | `SET LOCAL lock_timeout` 报 42704，记忆初始化提前失败 | 按目标能力改为 `lockwait_timeout`，核对毫秒单位及超时语义 |
| OG-07 | `array_agg(ARRAY[...::bytea,...])` 报 42704：could not find range type for data type bytea[] | 检查点读取需要另外适配；JSON 聚合 + Base64 还原的原型已通过 |
| OG-08 | 测试夹具 `GRANT ALL ON SCHEMA public TO CURRENT_USER` 报 42601 | openGauss 测试夹具使用明确且安全引用的角色标识；原有测试结果不能当作业务 CRUD 已实际执行 |
| OG-09 | gs_dump 不接受 pg_dump 风格的 `-d` 参数 | 分别构造 gs_dump / gs_restore 命令；gs_dump 使用位置参数 DBNAME，不能仅替换可执行文件名 |

原生 UPSERT 的多唯一冲突复现：先写入 `(event-a, thread, 1, first)`，再以 `(event-b, thread, 1, second)` 写入并更新 payload，结果为 `(event-a, second)`。这说明发生线程序号冲突时也会更新原事件，无法等同指定 event_id 冲突目标的行为。

## 4. 初始化与升级

### 当前代码

- 控制面：直接调用现有 `run_migrations()`，因 IDENTITY 语法失败。
- 记忆：直接实例化现有 PostgresMemoryBackend，因 `lock_timeout` 参数失败。
- 检查点：现有 PostgresSaver.setup 在 `ADD COLUMN IF NOT EXISTS task_path` 处失败。

### 隔离原型

- 记忆：预先安装 4 个函数原型，再对锁超时参数和 meta 表的单主键 UPSERT 做两处精确适配，成功建成 **12 张记忆表**。这是早期原型记录；当前 worktree 已有独立 backend 和 baseline。
- 样例升级：事务内获取锁、检查 information_schema 后执行 ADD COLUMN、更新版本记录，两次运行均通过且原数据保留。此项只证明迁移原语与幂等方案；当前尚无正式 openGauss baseline/增量脚本，不能宣称 Octop 升级验收已通过。

## 5. 检查点适配原型

只改四处 UPSERT 仍不足够。测试依次确认迁移加列语法和二进制数组聚合也需处理。最终原型包含：

1. 覆盖四个单主键表的写入 SQL。
2. 将版本化迁移中的 ADD COLUMN IF NOT EXISTS 改为普通 ADD COLUMN，继续依赖检查点独立迁移水位保证不会重复执行。
3. 将当前读取路径的二进制数组聚合改为 JSON/Base64，并在构造 CheckpointTuple 前还原 bytes，继续使用原有序列化器。

已实际通过 LangGraph 的保存、新连接读取恢复、thread/namespace 隔离、重复写入幂等、人工 interrupt 后关闭连接再 resume。测试不调用 LLM。

未覆盖旧 checkpoint 格式兼容、全部 delta/history 查询路径、实际工具执行中断、多进程重启、长时间并发和大数据量。上述原型不作为已完成的 OpenGaussSaver 发布实现。

## 6. 逻辑备份与恢复

使用本地已有 openGauss 6.0.5 镜像中的原生工具，仅运行客户端命令；工具 build 与目标数据库一致。

- gs_dump 自定义格式导出成功，退出码 0。
- gs_restore 向另一新建空库恢复成功，使用 exit-on-error，退出码 0。
- 样例表 ID、公共 ID、文本、JSONB、tsvector 快照前后一致。
- 恢复后继续插入成功，序列和唯一约束未阻断正常写入；生成列重新计算正确，GIN 索引存在。
- 临时归档在本地临时目录中生成，验证后自动删除；工具容器自动删除，无数据库端口映射。密码通过运行时环境/管道传递，未写入脚本、归档说明或日志。

这是数据库级合成数据备份恢复演练，不是 Octop 系统归档、真实工作区文件与三层业务状态一致性恢复验收。后续 worktree 已接入 `create_system_backup/restore_system_backup`，隔离库系统归档用例在 `data/opengauss/archive-03.log` 通过（3 passed），尚未覆盖真实生产数据和完整工作区。
